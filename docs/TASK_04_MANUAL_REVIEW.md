# 任务四：开启逐题人工审核

当前入口：http://127.0.0.1:7862/ 。本机专用，复核人姓名和备注仅记录在本机忽略目录。

**最新状态：90/90逐题人工通过，原完整门禁26/26通过，已封存只读。** 以下操作保留作审核阶段说明；当前按钮禁用以保护日志哈希。修订须另建版本，不在封存记录上续写。交付见[TASK_04_DELIVERY](../reports/TASK_04_DELIVERY.md)。

## 操作

1. 填写实际复核人的姓名或昵称（2–80字符）。页面默认进入第一条尚未人工通过的题目，保留以前的人工记录。
2. 阅读问题、拟定答案或拒答理由、支持段、难负例及来源校核提示。
3. 确认无误后，亲自勾选四项检查并点击“已逐项核对，通过此题”。四项不会自动勾选。
4. 有问题时写明至少4个字符的原因，点击“需要修改”。这会记录未通过意见，不修改冻结数据。
5. 点击“下一条待人工审核题”继续。负责人批量批准不会跳过待人工审核的问题。

## 冻结版本与审核记录

- 既有负责人批准与逐题人工通过分别显示。开启审核不等于剩余问题已经通过，也不会自动满足原人工交付门禁。
- 原始技术文档、任务标准、90题数据正文和测试锁不变；当前审核只追加绑定原 annotation_sha256 的真人记录。
- 冻结模式核对启动快照中的四份数据、语料和数据清单哈希。内容变化时停止接收审核，须核对版本后重新启动。
- 修改请求不能直接改写冻结题目。修订需另建数据版本并重新审核，不能使用冻结测试题调参。
- 记录保存在 `.runtime/eval_review/reviews.jsonl`，不上传姓名、备注或完整日志。页面读取实时日志；冻结清单中的旧人工计数是当时快照，不在每次审核时改写。
- 全部逐题审核后仍需执行原正式交付校验并处理人工发布状态；页面不会自动改写原验收标准或宣布任务全部完成。

## 启动命令

在本仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe scripts/serve_eval_review.py --port 7862 --allow-frozen-human-review
```

不带该选项启动时，冻结版本保持原来的只读行为。开启后刷新已有浏览器页面以加载新的会话。
