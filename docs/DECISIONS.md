## ADR-001：以 Kotaemon 为第一版应用底座

- 日期：2026-11-07
- 状态：计划采用，待本地启动验证
- 背景：需要完整用户界面与真实文档问答体验，同时希望主要精力放在 retrieval、评测和可复现工程上。
- 决定：以 [Cinnamon/kotaemon](https://github.com/Cinnamon/kotaemon) 作为上游底座，固定具体 commit/tag；先运行原版，再加独立实验模块/适配层。
- 原因：该仓库提供用户界面、文档引用与可定制 RAG pipeline；许可入口标为 Apache-2.0。源仓库当前具备 hybrid 检索和 reranker 接入点，适合增量改造。
- 代价：上游较复杂，需先熟悉 Python 项目结构；FAISS 不应假设开箱即用，适配需单独验证。
- 验收：记录上游 commit、完成本地启动，上传规则资料并显示可靠出处。
- 复查条件：无法在当前机器/依赖下运行，或维护成本大于自建轻量检索服务时重新评估。

## ADR-002：第一轮只使用一个固定赛季的 IFAB 语料（已由 ADR-003 取代）

- 日期：2026-11-07
- 状态：已取代，未执行
- 背景：规则按赛季更新；混用版本会使问答答案与检索评测产生歧义。
- 决定：基线阶段固定单赛季、单语言；manifest 记录来源、下载日期和 hash。未经许可核实，不公开分发全文文件。
- 原因：结果可重复，能区分检索质量问题和法规版本差异。
- 代价：不能回答其他赛季规则；多版本对比留到后续。
- 复查条件：首轮需要验证历史规则变化或多语言问题时，创建独立语料和评测版本。

## ADR-003：先用 Wikimedia 足球规则专题页作为可采集语料

- 日期：2026-11-07
- 状态：原 MediaWiki API 方案未执行；实际采集偏差见 ADR-004
- 背景：IFAB 条款不适合作为未经授权的本地全文语料；项目需要可程序化读取且许可允许再利用的真实足球规则相关文本。
- 决定：采集英文 Wikipedia《Laws of the Game (association football)》及其直接链接的规则专题页，通过 MediaWiki API 白名单读取；记录 revision ID、时间戳和 SHA-256。
- 许可：逐页核对实际 CC BY-SA 许可；语料保留署名/许可链接，改编内容按相同方式共享要求发布；语料许可证与代码许可证分开。
- 代价/限制：这是社区维护的二手概述，不是官方规则全文。Wikimedia API 有速率限制，必须遵守。
- 验收：采集只访问白名单页面；输出许可/署名元数据；固定 revision；回答展示来源链接和二手资料提示。
- 复查条件：拿到 IFAB 书面授权，或找到许可明确且更权威的官方规则语料。

## ADR-004：网页读取快照作为首批语料的实际获取通道

- 日期：2026-11-10
- 状态：已完成首批快照；API 采集器仍未实现
- 背景：本机直连 Wikimedia API 超时，代理不可用；首批资料需要先形成可阅读、可整理的本地语料。
- 决定：本批实际保存网页读取通道返回的带行号文本快照，共覆盖 18 个来源页。快照不是原始 HTML，也不是 API 原始 JSON；来源页脚显示的 revision ID 已记录，但指定历史版本正文没有逐页独立回取验证。用快照文件和处理后文本的 SHA-256 固定本次内容。
- 影响：本批流程与 ADR-003 中计划的 API 获取方式不同。`scripts/build_rules_document.py` 只基于本地快照离线整理，不执行联网抓取。不得把本批来源描述为通过 API 获取或已验证所有历史版本正文。
- 后续：若实现正式采集器，仍需按 ADR-003 白名单读取，并为新获取内容创建新语料版本，不覆盖本批快照。


## ADR-005：先以稳定证据摘录修复回答与引用（2026-11-11）

- 状态：本机已启用，开发回归和真实 UI 已验证。
- 原因：原模型服务截断证据、独立工具引用多次为空，三条问答发生判罚或来源错配。
- 决定：保持固定上游及原语料只读，用本地 reasoning 覆盖层识别规则主题、细化到稳定单元；模型只选已有 ID，程序输出完整原段与对应来源；上下文逐请求固定，证据不足拒答。当前不用未经校验的自由改写。
- 代价：回答偏长，选段仍可能漏召回/冗余；16 条开发回归不证明全局准确率。正式统一数据、人工评测和原任务指标要求不变。
- 实现/回滚：见 ANSWER_QUALITY_FIX；FOOTBALL_QUALITY_GUARD 控制重启后使用覆盖层或历史 Simple QA。未改写上游 checkout 或五份语料。

## ADR-006：任务四 AI 候选与真实人工签收分别记录（2026-11-11）

- 依据：原任务四明确要求人工核对支持chunk、标注准则/人工记录与锁定测试不参与调参；原规则不修改。
- 决定：先交付可复核的40开发/50测试候选、90答案标签和90对负例；明确AI来源。结构检查、手算/坏数据检查、正式人工交付门禁分开输出。
- 人工：逐题页面展示本机支持正文、条件/例外、版本/校核提示和负例。真实复核人逐题确认，内容哈希绑定，禁止自动通过。合成签名仅在隔离夹具验证程序且默认不计真实确认。
- 冻结：全部匹配人工确认后才锁定；冻结后构建器拒绝覆盖，改题另建版本。参数选择只用开发集，正式测试计分要求锁定数据/配置快照和报告用途。
- 影响：人工未完成时任务四不能宣称交付，主线保持前三项已交付状态；候选放新任务分支/草稿PR，不提前执行任务五。
- 数据：仅分发自拟问题、标注/引用元数据，不分发原全文；姓名、备注、完整复核日志仅本机。源规则未经过裁判专家核验这一边界不因人工标注改变。

## ADR-007：任务五以固定BGE-M3制品建立独立Dense索引（2026-11-11）

- 依据：任务四已完成90/90人工核对与原26/26验收；原任务五要求先固定Embedding/存储、保留99段ID、从空目录重建，不提前混合检索或质量计分。
- 决定：复用现有Ollama0.40.16的bge-m3:latest，但以精确digest 7907646426070047a77226ac3e684fbbe8410524f7b4a74d02837e43f2146bab校验；1024维F16，CPU8线程。使用原section_path全路径加content_zh，L2归一化、Chroma0.5.16 cosine，显式禁用自动Embedding函数。
- 原因：本机16GB内存且已有模型/固定依赖；无需新增Torch安装或模型下载，易与上游现有Chroma栈衔接。CPU配置易复核，本轮不以更换硬件或索引参数追求提升数字。
- 隔离：新data/indexes/dense目录；不复用旧应用50块索引或回答缓存，不改7860/7861服务。向量、正文副本、SQLite/HNSW文件仅本机，公开模型/配置/制品哈希及99个ID映射。
- 版本：Ollama分发digest不是HF commit；每批前后核对模型，查询与文档共享固定维度/模板/归一化。Chroma配置按安装版源码记录，不把新版默认值套到0.5.16。
- 兼容：首轮Chroma/PostHog遥测接口提示后，使用独立DisabledTelemetry组件及必需的@override声明；不升级锁定依赖、不修改site-packages或上游。真实失败保留task5_before_runtime_fix.json。
- 验收：独立进程加载/查询、99条精确ID和metadata、二次真实编码重建及float32容差比较、坏向量/改模型/伪来源/覆盖拒绝、输入保全。结果以TASK_05_DELIVERY和task5_delivery_gate为准。
- 复查条件：进入后续正式开发集实验，或实际资源/部署需求变化。变更模型digest、模板或存储参数应建立新配置/索引版本，不覆盖已交付目录，不用锁定测试题调参。


## 任务六决策补记（2026-11-12）

- 复用固定上游、原99段正式Dense索引与两个精确Ollama模型，新增独立7863运行入口，不改旧实例或已冻结文档/数据。

- 检查格式、长度、残句、重复和数值；无效输出最多额外重试一次，保存全部尝试和不完整原响应；正常资料不足拒答不重试。数字存在/引用完整不能当作语义蕴含证明。
- 完整smoke、UI记录及失败保留本机，公开元数据/哈希；原评测不用于调参。正式答案质量和检索指标按原任务七/十二分别实施。
