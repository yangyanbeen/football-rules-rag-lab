原计划“开发30–50、测试至少50”为建议数量。本版本选择40/50作为自身可复核约定，没有把建议改写成原文硬性标准。

## 3. 字段与标注准则

| 字段 | 规定 |
| --- | --- |
| question_id | D001–D040 / T001–T050，稳定唯一 |
| question、topic、intent_group | 中文用户问题、主题与意图分组，不放模型答案 |
| expected_chunk_ids | 能支持本题要点的稳定 ID；可回答至少1个，拒答必须空 |
| answerable、must_refuse | 严格布尔且相反，不用字符串 true |
| difficulty | easy / medium / hard；表示问题判断难度，不是模型实测难度 |
| law_numbers、categories | 规则号1–17及数字/术语/条件/例外/跨段/版本/资料外类别 |
| required_conditions | 回答必须覆盖的条件、例外、数值或概念；不能删掉改变结论的限制 |
| refusal_reason | 资料外或版本/赛事不充分的具体理由；可回答题为空 |
| source_references | 由原数据自动展开 URL、source ID、行号、内容哈希、可见修订及未独立核验/翻译/专家状态 |
| hard_negative_ids、hard_negative_content_sha256 | 关联独立难负例及其内容/理由哈希；不能把支持 ID 同时当负例 |
| annotation_sha256 | 问题、要点、来源、分组及难负例哈希的规范 JSON SHA-256 |
| expected_answer_points | answer_eval 中逐条对应 required_conditions；不是已生成系统回答 |

标注针对固定资料：明确的规则概念可给要点；数字保留来源单位和近似/版本限定。存在 needs_rule_review 的支持段，不会因成为 gold 候选就变成已审校。历史坠球、赛季变化、未给赛事的纪律罚款等必须保留限制；不能由相似段落推断缺失的官方答案。

可回答题中的多个 ID 表示已标注支持集合；跨段题须覆盖全部必要部分。相似但只支持其他条件、其他重启或不同判罚类型的段落不能作为充分证据。已知支持标签可能不是穷尽相关性判断，人工应补充真正等价的支持 ID；不能把未标注相关段一概当负例。

难负例的理由必须说明“哪里相近、缺什么条件/属于什么不同对象/为什么不能得出本题目标”，不能只写“不相关”。版本不明题可引用一段相似年份概述作为难负例，理由应明确该段不能证明官方现行适用性；这不表示那段完全没有背景价值。

## 4. 实际人工复核

```powershell
.\.venv\Scripts\python.exe scripts/serve_eval_review.py --port 7862
```

打开 [本机逐题复核](http://127.0.0.1:7862/)。实际复核人填写姓名/昵称，读取每题支持正文、拟定要点、难负例及来源/校核提示，必要时搜索其余99段。完成四项核对后选择“通过”；有问题写明原因并选“需要修改”。每题单独记录，不提供批量自动通过。

姓名、备注和完整本地记录不进 Git。只有事件声明 human、判定通过、时间有效、四项检查完成且内容哈希仍匹配，才计人工通过；AI签名、过期哈希、合成夹具记录均无效。该确认是人工证据标注复核，不是裁判专家对规则现行有效性的认证。

有修改意见时编辑 annotations.json，重新运行 build_eval_dataset.py 和验证器。只要该题内容/来源/负例理由变化，旧确认就失效，必须重新复核；其他未变题可保留真实确认。页面会按 manifest 刷新数据；提示哈希已变时刷新当前题。全部确认完成前，不进入任务五。

**本轮记录：**实际人工确认0/90（报告生成时）；没有把本 Agent 逐段阅读或程序校验写成人工签收。最初版本有两道“所有赛事是否都必须”的拒答题容易同“可回答：不一定”混淆，已改为具体但缺赛事/赛季信息的数值/制度查询。这是 AI 草稿修订，不是人工审校成果。

## 6. 指标口径与手算验证

按原技术文档，Recall@5/10 是“可回答题至少一个正确证据出现在Top-K”的题目比例；不是逐文档召回分数。MRR@10 是首个正确证据名次倒数，未入前10记0。多证据全覆盖另列 all_gold_coverage@5，避免一个命中就误称已覆盖跨段答案。不可回答题不进检索分母，其拒答质量留任务十二。没有分级相关标签不报告nDCG。

手算夹具只用虚构ID：A有两个正确ID且首命中第2，B首命中第6，U无答案。预期 Recall@5=1/2，Recall@10=1，MRR@10=(1/2+1/6)/2=1/3，平均全部支持覆盖@5=1/4。脚本实际复算一致。这些是程序算术测试值，**不是本系统检索成绩**。

任务四还实际注入16类重新签哈希的坏数据，以及缺预测、重复排名、AI/过期/未来/不完整人工记录、未冻结测试和错误配置等，验证拒绝路径。完整冻结/复建拒绝的正向流程仅在显式 .tmp 合成夹具里测试；合成记录不能用于真实门禁。
