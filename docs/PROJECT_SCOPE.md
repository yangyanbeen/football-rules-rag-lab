# 项目范围与需求基线

最后更新：2026-11-07

## 产品目标

为中文用户提供基于足球规则资料的问答。回答应给出规则编号/来源，缺少证据时说明无法从当前资料确定；使用 Wikipedia 语料时明确标注为社区维护的二手概述。

## 目标用户与问题

- 目标用户：想快速查足球比赛规则的球迷、球员或初学裁判。
- 典型问题：越位如何判定？点球重罚的条件是什么？守门员持球时间如何规定？涉及赛季的问题必须识别用户指定的版本；若当前资料无法权威确认该赛季，应明确说明范围限制，不推断为现行官方规则。
- 首轮使用英文 Wikipedia 规则专题页做可采集语料，只作为社区概述问答演示；当前资料并非一个固定赛季的 IFAB 官方规则集。回答标注来源，不宣称是 IFAB 官方裁定。

## 必须交付

- 可本地运行的用户界面；文档导入、提问、显示出处。
- 固定版本语料和可复现评测集。
- baseline、BM25、dense、RRF、reranker、结构切分的逐步对照。
- 明确的检索质量、引用、拒答和延迟口径。
- 公开代码不含密钥、受限原文或用户个人信息。

## 非目标

- 自研/训练基础模型；实时比分；未经来源支撑的规则解读；没有评测的优化宣称。
- 初始版本不承诺 FAISS 或缓存必须落地；它们是后续可选实验。

## 需求变更规则

新增功能前必须写：用户问题、预期影响的指标、所需时间/复杂度、会延后的工作。先记入本文件的“待办候选”，每次只批准一个新范围项；不因临时想法打断当前验收项。被接受后更新本文件和 README，再新建独立 Issue/分支。
