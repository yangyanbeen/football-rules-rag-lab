## 执行链路是否完整保存

对固定90份 Worker 私有轨迹，链路保存情况如下：

| 链路环节 | 保存情况 | 具体字段/限制 |
| --- | --- | --- |
| 原始问题 | 是 | Worker wrapper/result 的问题文本、问题哈希；问题与评测题哈希绑定。 |
| 改写后的 Query | 单轮可确认；多轮有条件 | `query_resolution`、`result.question`、`retrieval.query` 保存；单轮没有改写时保持原问题。旧轨迹未必保存改写模型的完整调用次数。 |
| Dense/BM25 召回及分数 | 是 | `retrieval.channels` 保存两路段、rank、score/distance；`before` 保存融合结果与分数/排名；阶段耗时也保存。 |
| Rerank 结果 | 是 | `retrieval.reranker.results` 保存段 ID、rank、score、输入/正文哈希和截断观测。 |
| 最终上下文 | 是 | `context`、`offered_ids`、完整 `messages`、Prompt SHA256、UTF-8 字节数和装配遗漏保存。 |
| LLM 输出 | 是 | `attempts` 保存原始响应、解析结果、错误、调用耗时；最终 `status`、`answer`、`selected_ids`、引用和拒答原因保存。 |
| 评测结果 | 是 | 每题 grade、要点/条件 mask、引用支持审核、错误归因和固定指标保存；语义审核不是裁判专家人工认证。 |

结论是：**固定90题的默认 Worker 轨迹基本具备完整单轮执行链路，可以做本次归因。** 但还不能说所有入口和所有场景都完整：多轮 Session 隔离、改写调用计数、并发队列和 LangGraph 的完整生产者轨迹仍有缺口；没有原始 observations 的公开 Graph 最小轨迹不能冒充 Worker 全链路。
